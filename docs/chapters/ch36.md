**Content classification.** Bucket A (CVP and pulmonary-artery-catheter waveform

#### 20.1 CVP Waveform Model (`src/engine/CvpWaveformModel.js`)

New engine. `patient.hasCVC` already existed (set when a central line is placed) but
drove no waveform at all — only a flat numeric `vitals.cvp` mean. Added:
*   `calculateCvpWaveComponents(patient, vitals)`: pure classifier returning a/c/v wave
    heights and x/y descent depths, scaled proportionally to the live `vitals.cvp` mean
    (Table 36.2's a/v heights are tabulated at exactly one mean — there is no
    source-given scaling rule, so this is a disclosed generalization, not a citation).
*   `tracePhasicAtrialPressure(p, comp)`: the shared a/c/v/x/y/h phase-shape engine
    (Table 36.3 timing), extracted as a standalone exported function the moment a second
    consumer (the PAC wedge trace, §20.2) needed the identical shape — per this project's
    standing "extract into a shared pure function" convention.
*   `synthesizeCvpWaveform(...)`: canvas-pixel synthesizer, wired into `CanvasWaveform.jsx`
    (`type="cvp"`) and a new always-on-when-`hasCVC` strip in `PrimaryMonitor.jsx`.
*   **Patterns implemented**: normal; atrial fibrillation (reuses the existing
    `patient.afib`/`cardiacRhythm==='afib'` — a wave lost, c wave boosted); AV
    dissociation/asynchronous pacing (new `patient.avDissociation` flag — tall cannon a
    wave); tricuspid regurgitation (new `patient.tricuspidRegurgitation` flag — fused
    tall c-v wave, obliterated x descent, drops the a wave too if AFib coexists, matching
    the chapter's own Fig 36.37 worked example).
*   **Deliberately deferred** (disclosed gap, not an oversight): tricuspid stenosis and
    pericardial constriction/tamponade's full M/W-configuration equalization pattern —
    both real Table 36.4 entries, held back to keep this session's pattern set clearly
    bounded. Pick up if a future session needs them; the shared phase-tracer already
    supports adding new height/depth parameter sets cheaply.

#### 20.2 Pulmonary Artery Catheter Model (`src/engine/PulmonaryArteryCatheterModel.js`)

Entirely new — no PAC/PCWP/thermodilution modeling of any kind existed anywhere in the
codebase before this session.
*   **`calculatePacPressures(patient, vitals)`**: derives PA systolic/diastolic from the
    already-dynamic `vitals.mPAP` (`HepaticEngine.ts`, driven by cirrhosis/portopulmonary
    hypertension) while exactly preserving the live mean via the MAP-style
    $mean = diastolic + \frac{pulsePressure}{3}$ relationship, scaling Table 36.2's pulse
    pressure proportionally. PCWP starts from the already-dynamic `vitals.lvedp`
    (`CardiovascularEngine.ts`) and adds disclosed, reasoned overestimation offsets for
    PEEP > 10 cmH2O and mitral regurgitation (new `patient.mitralRegurgitation` flag),
    per Table 36.5's documented discrepancy *directions* (the source names the direction
    of each discrepancy, not a literal mmHg magnitude).
*   **PA trace shape**: sharp systolic upstroke, then a diastolic floor that *falls*
    continuously through diastole — confirmed directly against Fig 36.38's pixels as the
    key visual/physiologic differentiator from the right ventricle (whose pressure
    *rises* through diastole as it passively fills). This distinction would not have
    been derivable from the auto-extracted figure caption/metadata alone.
*   **Wedge/PCWP trace**: reuses §20.1's shared `tracePhasicAtrialPressure`, scaled to a
    damped left-atrium proxy (Table 36.2's LA row, the closest tabulated analog to a
    transmitted wedge reflection). Mitral regurgitation shifts the v-wave peak into early
    systole (`vEarlySystole`) and fuses/obliterates the x descent, matching Fig 36.41/42.
*   **Artifacts**: `patient.pacWhipArtifact` (catheter-motion ripple at systole onset —
    the chapter's most common real PAC artifact, Fig 36.39's true-PAD-8-displayed-as-0
    example) and `patient.pacOverwedged` (non-pulsatile climbing pressure, Fig 36.40).
    Both are engine-level capabilities only this session — set directly on patient state,
    not yet wired to an automatic trigger condition (see §20.6).
*   **`PAC_INSERTION_SEQUENCE`/`PAC_POSITIONING_AIDS`** (Bucket C groundwork): the
    RA→RV→PA→wedge insertion-transition sequence (depths, waveform differentiators,
    troubleshooting thresholds at 40/50 cm) and positioning aids, captured as structured
    data for a future procedural-practice engine — not built as an interactive insertion
    UI this session, per this project's standing procedural-content deferral convention.

#### 20.3 Arterial Line Dynamic Response (`calculateDynamicResponse`, `ArterialLineModel.js`)

`ArterialLineModel.js` already drove the live waveform from a discrete damping state
(`patient.alineDamping`, or inferred from a 22G catheter gauge) but had no way to
express that state as the natural-frequency/damping-coefficient numbers a real fast-flush
test would read. Added `calculateDynamicResponse(patient)`, anchored to the chapter's one
worked example (1.7 mm oscillation period at 25 mm/s → 14.7 Hz; 17/24 mm consecutive peak
heights → 0.71 amplitude ratio) — confirmed directly from Fig 36.25's pixels, since the
chapter gives the worked inputs/outputs but not the intermediate log-decrement formula.

#### 20.4 Frontend (`PrimaryMonitor.jsx`, `Modals.jsx`, `App.jsx`)

*   New CVP strip (blue, gated on `patient.hasCVC`) and PA-catheter strip (orange, gated
    on `patient.hasPAC`) added to the primary monitor's waveform column, alongside the
    existing ECG/ART/PLETH/EEG strips — same conditional-rendering pattern as the
    pre-existing ART strip.
*   The PA-catheter strip includes an inline toggle (a local `paWedged` view-state, not
    deep patient state — wedging is a display-mode choice between two already-computed
    traces, not a separate physiology simulation) switching between the live PA trace and
    the wedge/PCWP trace, with a compact PA/PCWP numeric readout.
*   `Modals.jsx`'s Central Line access modal gained a 4th catheter-type option
    ("Pulmonary Artery Catheter (Swan-Ganz)"); `App.jsx`'s `establishAccess()` handler
    sets the new `hasPAC` flag alongside the pre-existing `hasCVC` logic (one added line).

#### 20.5 Knowledge Layer & Outcome Scoring (`ClinicalAiChat.js`, `App.jsx`)

*   Two new Attending-chat-reachable answers: CVP/PAC waveform interpretation (keyed on
    "cvp"/"wedge"/"pcwp"/"swan"/"cannon"/etc., grounded in live state when a line/catheter
    is placed, falling back to general reference guidance otherwise) and arterial-line
    dynamic response (keyed on "fast flush"/"damping"/"natural frequency"/etc.).
*   One new `QualityEvent` (`Monitoring`, `info` severity), fired once at PAC placement in
    `App.jsx`, reminding the user that the digital PA/PCWP readout can be misled by
    catheter whip or overwedging — a neutral vigilance marker rather than a scored
    mistake, since neither artifact is yet tied to an automatic in-session trigger (§20.6).

#### 20.6 What Was Not Integrated / Deliberately Deferred This Session

*   Tricuspid stenosis and pericardial constriction/tamponade's CVP patterns (Table
    36.4) — disclosed gap, see §20.1.
*   `pacWhipArtifact`/`pacOverwedged` are engine-level capabilities with no automatic
    trigger condition — a future session could tie overwedging to "balloon left inflated
    too long" (would need `paWedged` promoted from PrimaryMonitor's local view-state into
    real tick-loop-visible patient state to track elapsed wedge duration) or whip artifact
    to a probability tied to tachycardia/dysrhythmia.
*   TABLE 36.6 ("Overestimation of LVEDP") could not be transcribed — the source PDF's
    two-column page layout caused the extraction pipeline to merge its title into Table
    36.5's continuation fragment with no corresponding row-content entry anywhere in the
    64 `visual_data_engines` records. Not recoverable from this parsed JSON; would need a
    fresh look at the original PDF's page ~39 region in a future session.
*   Esophageal Doppler, transpulmonary/lithium-dilution/bioreactance/CO2-rebreathing
    cardiac-output techniques, the full ECG-artifact-source catalog (Box 36.1), and the
    NIBP/arterial-line complication-rate statistics (Boxes 36.2-36.4) were extracted in
    full (see the research sub-agent's report) but not wired into any live mechanic this
    session — they remain available as background Attending-chat knowledge-base context
    rather than a dedicated feature, since none of them mapped as cleanly onto an
    existing or easily-added engine signal as the CVP/PAC/dynamic-response work did.
*   The RA→RV→PA→wedge insertion sequence is structured data only (§20.2), not an
    interactive placement UI — consistent with this project's standing procedural-content
    (Bucket C) deferral.
